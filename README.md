# 我的桌面计时器

一个用 Python + Tkinter 写的桌面秒表，单文件、无第三方依赖。

---

## 一、功能

- 大号数字显示区，格式为 `时:分:秒`，启动时显示 `00:00:00`
- 三个按钮：**开始** / **暂停** / **重置**
- 深色扁平化界面，窗口启动时自动出现在屏幕中央
- 支持键盘快捷键操作

## 二、运行环境

| 项目 | 要求 |
| --- | --- |
| Python | 3.x（在 3.10 上验证通过） |
| 第三方库 | 无 |
| 依赖模块 | `tkinter`、`time`，均为 Python 标准库 |

> `tkinter` 在 Windows / macOS 的官方 Python 安装包中默认自带，一般不需要额外安装。
> 如果运行时报 `ModuleNotFoundError: No module named 'tkinter'`，说明用的是某些精简版 Python（如部分 Linux 发行版需 `sudo apt install python3-tk`），换用官网安装包即可。

## 三、启动方式

### 方式 1：命令行（推荐，最稳定）

```bash
cd F:\DesktopTimer
python timer.py
```

窗口弹出后，**终端窗口会一直被占用**，这是正常现象——计时器关闭后终端才会回到提示符。

### 方式 2：双击运行

直接双击 `timer.py`。前提是 `.py` 文件已经关联到 Python 解释器。

### 方式 3：不要黑色终端窗口

把 `timer.py` 复制一份改名为 `timer.pyw`，双击 `timer.pyw` 就只会出现计时器窗口，不会附带终端窗口。
（等效于在命令行执行 `pythonw timer.py`。）

## 四、操作说明

| 操作 | 按钮 | 快捷键 | 说明 |
| --- | --- | --- | --- |
| 开始计时 | 开始 | `空格` | 从头计时；暂停后按它继续累加 |
| 暂停 | 暂停 | `空格` | 停住显示，已计时间保留 |
| 归零 | 重置 | `R` | 停止计时并把时间清零 |
| 退出 | 窗口右上角 × | `Esc` | 关闭程序 |

`空格` 是"开始 / 暂停"的切换键：计时中按它等于暂停，停止中按它等于开始。

## 五、行为细节

这几点是刻意这样设计的，不是巧合：

1. **暂停后按"开始"是继续计时，不是重新开始。** 比如走到 `00:00:30` 暂停，再按开始会从 30 秒继续往上走；只有"重置"才会归零。
2. **计时精度不受界面刷新影响。** 内部用 `time.monotonic()` 记录起止时刻、用时间差算总时长，而不是每刷新一次加一秒，所以就算程序卡顿或系统繁忙，长时间跑也不会累积误差。
3. **界面每 100 毫秒刷新一次，但只显示整秒。** 因为 `00:00:00` 的格式没有小数位，不足 1 秒的部分会向下取整——所以在 0.9 秒时看到 `00:00:00`、到 1.0 秒才跳到 `00:00:01`，这是正常的。
4. **重复点击有保护。** 计时中再点"开始"、已停止时再点"暂停"，都会被忽略，不会出现时间跳变或翻倍。
5. **小时位是两位宽，超过 99 小时会自动扩宽**（例如显示 `100:00:00`），不会报错。
6. **关闭窗口时会先取消定时器**（`after_cancel`）再销毁窗口，避免退出时报错。

## 六、常见问题

**Q：提示 `'python' 不是内部或外部命令，也不是可运行的程序`**
说明安装 Python 时没勾选 "Add Python to PATH"。可以改用 Windows 自带的启动器：

```bash
py timer.py
```

**Q：双击后黑框一闪就没了**
说明双击打开的方式把程序当成脚本执行完就退出了，通常是 `.py` 没关联好。改用命令行的方式 1。

**Q：窗口弹出来了，但没有反应 / 按钮点不动**
检查是不是终端里报错了（比如缺少 tkinter）。把终端里的报错信息发出来即可定位。

## 七、文件说明

| 文件 | 说明 |
| --- | --- |
| `timer.py` | 程序主文件，共 167 行，可独立运行 |
| `README.md` | 本说明文档 |
| `.gitignore` | 忽略 `__pycache__`、虚拟环境、编辑器配置等不需要入库的文件 |

`timer.py` 内部结构：

- `TimerApp` 类 —— 程序主体
  - `_build_ui()` 搭建界面、`_center_window()` 窗口居中、`_bind_keys()` 绑定快捷键
  - `start()` / `pause()` / `reset()` 三个按钮对应的逻辑
  - `total_seconds()` 计算当前总用时
  - `_tick()` 每 100ms 执行一次的刷新循环
  - `_render()` 把秒数格式化成 `时:分:秒`
- `main()` —— 创建窗口并进入事件循环

### 让 Claude 代为提交

直接说「**改动描述 + 提交并推送**」，例如"把字体调大了，提交并推送"。

| 说法 | 实际动作 |
| --- | --- |
| 把字体调大了，提交并推送 | 提交 + 推送 |
| 修好了暂停的 bug，提交并推送 | 提交 + 推送 |
| 只提交，先别推送 | 只做本地提交，GitHub 不动 |
| 看看我改了什么 | 只给你看 `status` / `diff`，不动仓库 |
| 推上去 | 用上次说过的改动内容提交并推送 |

约定：

- 提交信息用中文，动词开头一句话说明做了什么，多条改动分点列出
- 只是"提交"而没有说"推送"，**默认只做本地提交**——本仓库是 Public，推送等于公开发布
- 推送前会先把提交信息和将要上传的文件清单报出来
- 建议在描述里说清**为什么改**，而不只是改了什么：`git diff` 只能看出哪几行变了，意图只有你知道，而这决定了提交信息怎么写

### 网络问题（重要）

本机 `github.com` 直连会被重置。浏览器能打开 GitHub 是因为走了系统代理，但 **git 不读取 Windows 系统代理**，所以命令行直连一定失败。本仓库已经把代理写进 `.git/config`：

```
http.proxy = http://127.0.0.1:7897
```

如果某天推送报 `Connection was reset`，多半是代理工具重启后换了端口，按新端口更新即可：

```bash
git config http.proxy http://127.0.0.1:新端口
```
